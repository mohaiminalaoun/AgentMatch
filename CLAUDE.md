# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm test`: run all tests once (Vitest)
- `npx vitest run tests/engine/profile.test.ts`: run one test file; add `-t "<test name>"` to run one test
- `npm run test:watch`: run tests in watch mode
- `npm run typecheck`: type-check with `tsc --noEmit` (nothing is emitted; code runs through `tsx`)
- `npm start`: run `src/index.ts` with `tsx`
- `npm run eval`: compare all matching methods across seeds and print a results table: team quality, share of people placed, per-person quality, leakage (share of private fields reaching people outside their team), and whether a trusted central party is needed (`src/evaluation/run.ts`)
- `npm run ask "<prompt>"`: send one prompt to the model configured in `.env` and print the reply, token usage, and latency (`src/ask.ts`; costs real credits)
- `npm run decide [1-5]`: one agent decides on one sample proposal from `src/scenarios.ts`, printing the messages, its private rationale, gate blocks, and what would be sent (`src/decide.ts`; costs real credits)
- `npm run reliability`: run 20 live agent decisions concurrently over `src/scenarios.ts` and report the decision mix, gate blocks, a re-check that nothing sent breaks the disclosure rules, tokens, and time (`src/reliability.ts`; costs real credits)
- `npm run round`: one live round on the bus (Ivan proposes to Ben; Ben's agent decides and replies), printing each bus event, the private rationale, and both agents' state (`src/round.ts`; costs real credits)
- `npm run negotiate`: Nia proposes to Kemi and the two negotiate over the bus tick by tick up to level 2, printing every message, levels after each tick, every private rationale, and what each side learned (`src/negotiate.ts`; costs real credits)
- `npm run coevolve`: Theo (a workout tracker) proposes to Mara (a rehab coach), each with level-tagged private notes; they negotiate to level 2, where either may propose a reshaped version of the project (a revision the other adopts or keeps), then commit. Prints every event with private rationales, then the original idea next to the version the team builds (`src/coevolve.ts`; costs real credits)
- `npm run hunch`: Lena pitches a fitness app to Rafa; his agent decides twice, with his profile only and then with his "never" note (a failed jiu-jitsu app) feeding a private hunch, printing both decisions and checking the note reaches nothing sent (`src/hunch.ts`; costs real credits)
- `npm run discover`: the six sample people's agents write board listings, then pick whom to approach; prints the listings, the board, each choice with its private rationale, and the resulting proposals, without negotiating (`src/discover.ts`; costs real credits)
- `npm run simulate [-- --agents N --rounds R --seed S --private]`: the whole system on generated people (default 10 agents, up to 6 rounds, seed 1): listings, then discovery, negotiation, and commitment each round, all concurrent, until a round changes nothing; prints every event as it happens (private rationales only with `--private`), a live status line of model calls, tokens, and time, and a report (pairs reached, committed teams, never-approached agents, roles beyond the core four on the board, gate blocks, calls, tokens) (`src/simulate.ts`; costs real credits: roughly 100–200 calls at 10 agents, 300–450 at 20)
- `npm run eval:agents [-- --people N --seeds 1,2,3 --rounds R]`: run the full agent simulation on the same generated people as the baselines (default 20 people, seeds 1–5, all seeds at once) and print one table with every method, agents included; saves `results/eval.json` (synthetic data only) for the chart, and logs each seed's run to `runs/` (`src/eval-agents.ts`; costs real credits, roughly 2,000 calls at the defaults)
- `npm run eval:explain -- <log> [--per-kind N --seed S]`: samples up to N private rationales of each call kind from a run log (default 5, seed 1), has a judge model sort every claim in each as supported by the agent's prompt, unsupported, or contradicted, and asserted or hedged, and prints a table per call kind; saves every judgment next to the log in `runs/` (`src/eval-explain.ts`, `src/evaluation/explain.ts`; costs real credits, one call per rationale; refuses a `-contributor` judge for logs with real people)
- `npm run eval:explain:label -- <explain.json> [--claims N --seed S]`: checks the judge against a person's labels. Writes a page next to it in `runs/` with N claims (default 30, up to half of them ones the judge flagged), each with the agent's prompt and rationale but never the judge's verdict, to label in the browser and download; then `--labels <labels.json>` prints verdict agreement, Cohen's kappa, flag precision and recall, a confusion table, and every disagreement (`src/eval-explain-label.ts`; no model calls)
- `npm run regressions [-- --runs N --case <name>]`: runs fixed, made-up scenarios that replay each reasoning failure seen in the pilot (role omission, join request, invented scheduling, headcount, misdescribed option, relabeled roles), plus declining an unfinished team seen in checkpoint B and dropping or withdrawing over roles neither of a pair can do, N times each (default 10), on the engine's real prompts; a judge answers one yes/no question per run, and it prints a failure rate per case with examples, saved to `runs/` (`src/regressions.ts`, `src/evaluation/regressions.ts`; costs real credits, two calls per run)
- `npm run eval:decisions -- <log> [<log> ...]`: checks each run log's decisions for hard problems, by code alone: final teams bigger or smaller than a member's limits, roles a team's project needs that no member can do (or only a beginner can), and offers the code sent differently from what the owner's model chose; prints ids only, never rationales (`src/eval-decisions.ts`, `src/evaluation/decisions.ts`; no model calls)
- `npm run baseline -- <label> <log> [<log> ...]`: freezes one record of how the agents do, to compare later changes against: the eval table, each log's explanation summary (its `.explain.json` from `eval:explain`), the newest regression results, and the decision check, as aggregates only, in `results/baseline-<label>.json`; refuses logs with anyone not generated, since `results/` is in git (`src/baseline.ts`; no model calls)
- `npm run chart`: draw the privacy vs. quality chart (per-person team quality against leakage, agents highlighted, baselines in gray, rings for methods that need a trusted party) from `results/eval.json` into `results/chart.svg`, with light and dark colors (`src/chart.ts`; no model calls)
- `npm run load-test [count]`: fire `count` (default 50) calls at once through the queued, retrying client and report 429s, retries, peak concurrency, and speedup (`src/load-test.ts`; costs real credits)
- `npm run show-run [file] [--prompts]`: print a run log from `runs/` as a timeline (ticks, bus messages, decisions and interest checks with their private rationales, level changes, and a model-call summary), defaulting to the newest; `--prompts` prints every model call in full. Logs are `runs/<timestamp>-<label>.jsonl`, one run event per line, gitignored because they hold every agent's private rationale and can hold real people's data
- `npm run pilot:run -- <dir> [--fill N --seed S --rounds R]`: the whole system on real people, one `.json` file each in `<dir>` (copy `profiles/example.json`; real profiles go in the gitignored `profiles/`), plus N generated people; refuses any `-contributor` model, keeps names unshared until people approve, and prints where each real person ended up (`src/pilot-run.ts`; costs real credits on the regular model)
- `npm run pilot:view -- <log> <id>`: prints one person's own view of a pilot run: the public board, their agent's steps with its private reasoning, and messages to or from them, never anyone else's (`src/pilot-view.ts`; no model calls)
- `npm run format` / `npm run format:check`: run Prettier (tabs, width 4)

## Architecture

Agent Match is a network of personal AI agents that negotiate to form teams for their humans, with no central coordinator. Agents reveal profile information in stages, and a deterministic disclosure gate outside the LLM blocks any message that reveals more than the current stage allows. Privacy must never depend on the model following instructions.

The code lives in `src/` in three areas:

- `src/engine`: core agent logic (domain schemas, proposals, the disclosure gate, the LLM client). LLM calls layer as `createLlmClient` (concurrency limit via `queue.ts`, backoff on 429/5xx via `backoff.ts`) → `chatJson` (re-asks on invalid JSON) → `chat` (one HTTP request); agents should share one client. Each agent may hold its human's private notes (`notes.ts`): free text tagged with a level (0–3, or "never"). Every prompt gets the full profile (whose short, known values the gate can find in anything sent) but only the notes its level allows (`aboutHuman`), since a paraphrased note can't be detected: a note that isn't in the prompt can't leak. Notes are never shared as data. An agent with "never" notes first makes a private hunch call (`hunch.ts`) that sees every note but can only output a steer (neutral, explore, careful, stop) and a risk area from fixed lists; code turns that into a fixed sentence for the decision or interest prompt, which never sees the notes. "stop" declines or withdraws with no call; "careful" rules out a plain accept. Every decision prompt judges by one shared standard, `GOOD_TEAM` (`goals.ts`), which weighs the criteria together and judges a team still forming by what it can become, and gets a labelled block of facts, estimates, and unknowns about the other person (`fitFacts`/`factsText` in `fit.ts`), computed by code from the agent's own profile and only what was shared with it (time zones, hours, skills, the team sizes that suit both, exact shared interests, a 9-to-5 overlap estimate stated as an assumption), plus `CITE_FACTS`: rationales rest on those facts and never state unknowns as fact. Agents decide through `decideOnProposal` (`decision.ts`), which runs every outgoing message through the disclosure gate (`gate.ts`); the model's `rationale` stays private and is never sent. Agents never call each other: every message goes through the bus (`bus.ts`), which validates it (schema, sender identity, recipient), delivers a copy to the recipient's inbox, and reports numbered events to subscribers for logging, the UI, and replay. `runRound` (`round.ts`) sends new proposals, then runs ticks until no mail is waiting (or `maxTicks`): each tick every agent handles its whole inbox, model calls run concurrently, and replies go out in inbox order so the bus order doesn't depend on LLM timing. An accepted proposal or counter opens level 1, and both sides send a `share` of that level's fields, built by code from the profile and gate-checked; receivers `learn` it, then run an interest check (`interest.ts`) and send `continue` or `withdraw`, which carry no text. At levels 1 and 2, a `continue` may come with a `revision`: a reshaped version of the project, gate-checked at that level (at most 2 per conversation), which the other side adopts or keeps with a text-free `revisionAnswer`; at level 2 a revision must also list `covers`, who covers every role the new version needs and every role the agreed version needed (`proposer`, `recipient`, `open`, or `dropped`), and code checks each claim against the proposer's profile and what the recipient shared (`coverProblems` in `interest.ts`); at level 1 covers aren't allowed, since they'd reveal skills; `agreedVersion` (`agent.ts`) is the last accepted proposal or counter, or adopted revision, with its author, who owns the project (`projectOwner`), since a version's roles list names what's needed from people other than its author. Once both sides have continued at a level, the next opens, up to `maxLevel` (default 2; level 3, names, is for commitment). Each agent's model first writes its public board listing (`listing.ts`): a short title and a pitch from its project idea plus the roles the project needs from others (any of `ROLES`), gate-checked at level 0. Every version of a project (listing, counter, revision, offer) carries its title with it, gate-checked like the pitch, so adopting a version adopts its name, and a team is named after the version it builds. `runSimulation` (`simulation.ts`) chains it all: listings once, then each round `discover` → `runRound` → `runCommitment`, until a round has no proposals, commits, or departures (stable) or `maxRounds` is reached, emitting a `stopped` event. Then, if at least two people are still on no team, a brainstorm phase (a `brainstorm` event, then up to 2 rounds) lets them meet each other through `brainstorm` (`discovery.ts`): anyone left over may approach anyone left over, people with no idea included, with a fixed `BRAINSTORM_PITCH` and their missing core roles, if the pair never got past level 0; agreeing to brainstorm isn't an idea, so a team needs an adopted revision or accepted counter first, and whoever wrote that idea owns it, idea of their own or not; an agent that picked nobody isn't asked again until the board changes; `summarize` derives the report from the final world and the events. `runCommitment` (`commitment.ts`) turns ready pairs into committed teams by deferred acceptance: each project owner sends a binding `offer` to the people it's ready with who fill a role its listing still needs (or wrote the agreed version themselves, whose roles list names what's needed from others) and whose largest team size fits (its model ranks them if not all can be taken; `selectOffers` trims to a set where each can take a different needed role, one each, so someone who could do several roles takes just one (`assignRoles`), plus, for people the owner's model chose, a second person for a role already taken while the team would otherwise be smaller than someone's smallest size, and the team fits the smallest `maxTeamSize` among its members, as learned at level 2; the `offers` event records the model's ranking and everyone the trimming dropped, with the reason, from `explainOffers`, and everyone the owner reached level 2 with but could not offer a place, with the first check that ruled them out, from `explainCandidates`; and, before there is a team, when the versions agreed with each person the model chose would keep some of them out, the one version its model wrote for all of them (`teamVersionMessages`), written only when someone was cut over the version, which every offer then carries, only if it passes the gate at level 2 and reveals to each of them nothing learned from anyone else), but before any is sent, an owner with no team yet who is being offered a place decides whether to lead (send its offers) or join one of those teams (its own offers are never sent; the join holds only if the owner joined leads, otherwise it's busy that pass); then every other agent holding offers picks one at the same time (the commit and lead-or-join prompt, `commitmentMessages`, shows every option side by side in the same shape: the version each team builds, its size now, and the facts about the person behind it, its own team included when it could lead) and answers `commit` or `decline` (an owner that leads answers `busy`; unlike a decline, that can be offered again), and these passes repeat within the round until nothing changes; a commit adds them to `world.teams` (the first member is the owner) and opens level 3. Each offer carries the version of the project the team will build: the team's once it exists, otherwise the version agreed (`agreedTerms`: the last accepted proposal or counter) with the first person offered; a version is only sent to someone if it reveals nothing the owner learned from anyone else (`safeToOffer`, using `checkThirdParty` in `gate.ts`), and the team's `rolesNeeded` come from it. The public board keeps the original listing. After a commit, so every pair of teammates swaps names, even ones who never talked. People on a team leave the board and stop discovering, except owners with places left and roles still needed. When a team grows, each earlier member (not the owner) re-checks: staying is the default, and leaving sends a text-free `leave` to each teammate, frees the place (the owner won't re-offer it to them), and raises the leaver's public `leftTeams`, which code attaches to their board entry and proposals so others can weigh reliability. Agents then choose whom to approach through `discover` (`discovery.ts`): each sees its own profile plus the public board (every agent's listing, nothing more; agents with a project also see the ids of people looking to join, who have no project and show nothing else), picks up to 3, and picks become proposals for `runRound`. Someone with no project asks to join instead: the proposal carries the target's own listing and is marked `join` (`isJoinRequest`), and the owner gets its own prompt (`joinRequestMessages`): the roles are its own project's needs, nothing is known about the requester yet, and it may only accept or decline. `runRound`'s `onEvent` emits one ordered stream of run events (`events.ts`: round, tick, bus, decision, interest, level, exchange); scripts write it to the run log and print it with `formatEvent` (`src/describe.ts`), so live output matches `show-run`. **It must never import from `src/ui`.** The UI subscribes to events the engine emits.
- `src/evaluation`: synthetic profiles, non-LLM baselines, and metrics (team quality, privacy leakage).
- `src/ui`: an Ink terminal UI that renders engine events.
- `src/pilot`: running real people. `person.ts` is a person's file (`{ profile, notes, contact }`; ids like `p-4k2m`, skills and preferred roles must be `ROLES`; `contact` never enters a prompt); `model.ts` refuses models the provider trains on; `run.ts` runs real plus generated people with `revealNames: false`; `view.ts` (`eventsFor`) is what one person may see of a run. The engine must never import it.

Domain types are zod schemas, and each TypeScript type comes from its schema with `z.infer`, using the same name (`export const Profile = z.object(...)` and `export type Profile = z.infer<typeof Profile>`). Validate any untrusted data, including LLM output, against these schemas. Tests live in `tests/`, which mirrors the `src/` layout (`src/engine/profile.ts` → `tests/engine/profile.test.ts`). Shared test data goes in `tests/fixtures.ts`.

## Conventions

- ESM with `NodeNext` resolution: relative imports need a `.js` extension (`import { Profile } from "./profile.js"`).
- LLM settings (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`) live in a gitignored `.env`; copy `.env.example` to create it. Entry points call `readEnvFile()` once, then pass `loadConfig(process.env)` down to whatever needs it. Never log the config or the API key.
- Optional `LLM_PRICE_*` settings (USD per million tokens) let reports estimate cost (`cost.ts`). The `-contributor` models are about 95% cheaper because the provider trains on their inputs: use them only with synthetic profiles, never with real people's data.
- Optional `LLM_REASONING_EFFORT` (`minimal`, `low`, `medium`, `high`) is sent as `reasoning_effort`. Hidden reasoning was about 95% of output tokens in simulations; `minimal` cut one decision from 25s to 2.5s.
- The tsconfig is strict, with `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, and `verbatimModuleSyntax`. Use `import type` for type-only imports.
- `steps.md` (the build plan), `readme-inprogress.md` (strategy notes), and `demo-notes.md` (demo moments and transcripts) are private and gitignored. Never commit them or copy their contents into tracked files. Work through `steps.md` one step at a time unless asked to combine steps.
- Use the `/commit-changes` skill for commits: one-line Conventional Commits messages, with no attribution lines.
